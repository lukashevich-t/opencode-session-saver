# AGENTS.md

Single-file opencode plugin (`session-saver.ts`): auto-exports opencode sessions as JSON in `opencode export/import` format into `ai-sessions/` in the repo root. There is **no** `package.json`, no build, no test infra — the whole codebase is one `.ts` file plus `README.md`.

## Verification

```sh
bunx tsc --noEmit session-saver.ts
```

Typecheck against the `@opencode-ai/plugin` SDK. Requires `bun` (opencode ships it; it is not installed on this host). There is no lint/test command — do not add test infrastructure.

## Deployment gotcha

The repo is just the source location. The running plugin lives at `~/.config/opencode/plugins/session-saver.ts`; edits in this repo have **no effect** until copied there and opencode is restarted:

```sh
cp session-saver.ts ~/.config/opencode/plugins/session-saver.ts
```

## Behavior invariants to preserve

These are the subtle parts the code implements; don't break them while editing. The final truth on behavior is `session-saver.ts` itself — the invariants below summarize it, and where they disagree with the code, the code wins:

- **Save timing**: sessions are saved only on activity switches and on `dispose()` — never per message/token. Subagent/subtask sessions (`parentID` set) are never saved or treated as switches.
- **All async work** must go through the `enqueue()` queue (serializes writes). `dispose()` races completion against a 4s timeout, and skips work until `warm` (index rebuild) finishes.
- **Index is derived from the exported files** (`rebuildIndex()` scans JSONs, uses `info.id`), not from opencode's DB. `sessionMap` maps `sessionID → {path, signature}`.
- **Signature dedup**: unchanged sessions (same title, update time, message count, and message/part ids) are skipped; on path change the old file is removed only after the new write succeeds. Writes are atomic (tmp file + rename).
- **Path scheme** `ai-sessions/<YYYY-MM-DD>/<HH-MM>_<slug>.json`: slug = slugified title (transliterated Cyrillic → Latin), truncated to `maxDescLen` (default 80), fallback `session_<8chars>` of the id. Same session within the same minute reuses/overwrites its file; different sessions get `_2`, `_3`, … suffixes.
- **Order of readiness checks in handlers**: `isTopLevel(id)` (with cached lookup) must gate save/activation so subagent activity never becomes "active".
- When `session.deleted` fires and `deleteOnSessionDelete` is on, remove the file + index entry, and clear `activeSession` if it pointed at the deleted session.

## Config

Config is JSON merged over defaults in `loadConfig()`. Precedence: global `~/.config/opencode/session-saver.json`, then project `.opencode/session-saver.json` (project wins). `root` is resolved relative to `baseDir` = the worktree unless it resolves to `/`, in which case the project `directory` is used.

## Runtime output

`ai-sessions/` (including `.index.json`) is generated by the plugin at runtime, not source. Per the intended cross-PC workflow it's meant to be committed/synced; it is currently untracked and not gitignored.
