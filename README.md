# session-saver (session-saver.ts)

Плагин для **opencode 1.18.x**, который автоматически сохраняет сессии в виде
обычных JSON-файлов в формате `opencode export` / `opencode import`. Позволяет
переносить историю диалогов с ИИ между разными ПК (или просто хранить её как
плоские файлы) **без опоры на внутреннюю базу данных opencode**.

Зачем это нужно: база сессий opencode лежит в `~/.local/share/opencode/` и на
разных машинах разная. Файлы, создаваемые этим плагином, лежат **в самом
проекте** (по умолчанию `ai-sessions/` в корне), их можно коммитить/синхронизировать
вместе с кодом. На другом ПК достаточно сделать `opencode import` — и история
продолжается.

---

## Установка
```bash
mkdir -p ~/.config/opencode/plugins && \
wget https://codeload.github.com/lukashevich-t/opencode-session-saver/tar.gz/HEAD -O - 2>/dev/null | \
tar -C ~/.config/opencode/plugins --strip-components=1 -xzf -
```

Через `curl` (с редиректами codeload):

```bash
mkdir -p ~/.config/opencode/plugins && \
curl -sL https://codeload.github.com/lukashevich-t/opencode-session-saver/tar.gz/HEAD | \
tar -C ~/.config/opencode/plugins --strip-components=1 -xzf -
```

## Как это работает

Плагин следит за событиями сервера opencode и делает экспорт активной сессии в
формате, который понимает `opencode import`:

```jsonc
{
  "info": { ...Session },
  "messages": [
    { "info": { ...Message }, "parts": [ ...Part ] }
  ]
}
```

Состояния сохраняются в **моменты переключения активности**, а не на каждом шаге:

1. **Создание новой сессии** (`session.created`) — сохраняется предыдущая активная.
2. **Явное переключение на другую сессию** — первое событие с другим `sessionID`
   завершает предыдущую сессию и переключает слежение на новую.
3. **Удаление активной сессии** (`session.deleted`) — удаляется её файл экспорта
   и запись в индексе.
4. **Выход из opencode** — в хуке `dispose()` активная сессия сохраняется
   финально (с таймаутом и защитой от падений).

Никаких периодических сохранений на каждый токен/шаг нет.

### Переключение и «продолжение» (`opencode -s`)

- Если вы переключили сессию в TUI (или через `opencode -s <id>`), плагин
  финализирует предыдущую активную сессию.
- Сессии-потомки (subagent/subtask, у которых задан `parentID`) **не** считаются
  переключением — активной остаётся родительская.
- При продолжении сессии (`opencode -s <id>` / `opencode -c`, той же сессии после
  `opencode import`) старый файл экспорта **перезаписывается** (тот же `sessionID`,
  та же минута → тот же путь). После нескольких действий в течение минуты путь не
  размножается: подтверждено, что переключение туда-обратно и `-s` сохраняют
  только один файл на сессию.

### Удаление

- `session.deleted` → файл экспорта и запись индекса удаляются (можно отключить).
- Если удаляют сессию, которая сейчас активна, слежение за ней снимается.

## Требования

- **opencode >= 1.18.x** (проверено на 1.18.31)
- **Bun** для запуска плагина (opencode поставляется с ним)
- TUI или серверное использование (`opencode run` / `opencode`)

## Установка

1. Создайте каталог глобальных плагинов, если его ещё нет:

   ```sh
   mkdir -p ~/.config/opencode/plugins
   ```

2. Скопируйте файл плагина:

   ```sh
   cp session-saver.ts ~/.config/opencode/plugins/session-saver.ts
   ```

3. Перезапустите opencode. Плагин подхватится автоматически из глобального
   каталога плагинов (добавлять его в `opencode.json` не нужно).

### Установка не куда-то ещё, а в проект (по желанию)

Плагин можно включить и только для конкретного проекта — через `plugin` в
`opencode.json` проекта:

```jsonc
{
  "plugin": [".opencode/plugin/session-saver.ts"]
}
```

## Конфигурация

Плагин читает JSON-конфиг (обычные ключи, окружение не требуется). Ищутся файлы
(побеждают проектные поверх глобальных):

- глобальный: `~/.config/opencode/session-saver.json`
- проектный: `~/.opencode (worktree) (или директория)/.opencode/session-saver.json`

Структура и значения по умолчанию:

```jsonc
{
  // Корень для сохранений. Абсолютный или относительно корня проекта.
  "root": "ai-sessions",

  // Сессии с количеством сообщений меньшим, чем это значение, не сохраняются.
  "minMessages": 1,

  // Максимальная длина описания (desc) в имени файла.
  "maxDescLen": 80,

  // Транслитерировать кириллицу в имени сессии (а -> a, б -> b, ...).
  // false — оставить как есть.
  "transliterate": true,

  // Удалять файл экспорта и запись индекса при session.deleted.
  "deleteOnSessionDelete": true
}
```

Пример `~/.config/opencode/session-saver.json`:

```jsonc
{
  "root": "ai-sessions",
  "minMessages": 1,
  "deleteOnSessionDelete": true
}
```

### Расположение файлов

По умолчанию:

```
<root проекта>/ai-sessions/<ГГГГ-ММ-ДД>/<ЧЧ-ММ>_<описание>.json
```

- `<ЧЧ-ММ>` — локальное время сохранения.
- `<описание>` — транслитерированный (кириллица → латиница) slug от заголовка
  сессии, обрезанный до `maxDescLen`; пустой заголовок заменяется
  на `session_<id_сессии>`-подобное id (например `session_08df6c2a`).
- Внутри каждой папки также лежит `.index.json` — индекс `sessionID → путь`,
  **пересобираемый сканированием самих файлов** (по `info.id`), не из базы opencode.

### Имена с коллизиями

Если в ту же минуту сохраняются две разные сессии с одинаковым описанием,
добавляется суффикс `_2`, `_3`, ... . Если сохраняется **та же** сессия повторно в
течение той же минуты (например, повторный экспорт при продолжении), файл
перезаписывается, а старый удаляется — без размножения.

## Перенос между ПК (основной сценарий)

1. Работали на ПК-1 — плагин сохранил файлы в `ai-sessions/` в проекте.
2. Закоммитили (или перенесли) директорию вместе с проектом на ПК-2.
3. На ПК-2 (в каталоге проекта) восстанавливаем сессию:

   ```sh
   opencode import ai-sessions/2026-09-16/13-21_my_session.json
   ```

   Импортированная сессия получит **исходный `sessionID`** (формат импорта его
   сохраняет).
4. Продолжаем:

   ```sh
   opencode run -s <тот-же-id> "продолжим"
   ```

5. При выходе (или переключении) плагин пересохранит её — старый файл будет
   заменён/удалён, новый создан. Работает и наоборот (ПК-2 → ПК-1).

Проверено: `opencode import` на другом ПК восстанавливает тот же `sessionID`,
дальнейший `-s` продолжает сессию, а плагин корректно пересоздаёт файл.

## Формат и безопасность записи

- Запись **атомарная**: пишется во временный файл, затем `rename` — файл никогда
  не остаётся полузаписанным при падении.
- Удаление старого файла при пересохранении: только после успешной записи нового.
- Повторный экспорт без изменений (та же сигнатура) — **пропускается**, лишних
  файлов не плодится.

### Сигнатура (для пропуска неизменённых сессий)

Считается как строка из: `title`, времени обновления, числа сообщений и
`id`-сообщений с их `part.id`. Считается одинаково и для живых данных, и для
прочитанного файла — поэтому при продолжении без изменений файл не
пересоздаётся, а при любом реальном изменении — заменяется новым именем.

## Режимы работы

| Режим | Поведение |
|---|---|
| Новая сессия в TUI | сохраняется при первом промпте + при выходе |
| `opencode run "..."` | сохраняется при выходе / переключении |
| `opencode -s <id>` (продолжение) | старая перезаписывается, файл не плодится |
| Переключение сессии в TUI | предыдущая активная финализируется |
| `session.deleted` | файл + индекс удаляются |
| Subagent/subtask (`parentID`) | не путается с переключением |

---

## Ограничения

- Сессии с `messages.length < minMessages` (по умолчанию 1) не сохраняются —
  пустые сессии не плодятся.
- Чтобы открытая «активная» сессия корректно досохранилась при резком убийстве
  процесса (SIGKILL), плагин полагается на `dispose()`/завершение worker-процесса.
  При нормальном выходе и в TUI сохранение гарантировано; при жёстком kill может
  не успеть — финальное сохранение произойдёт при следующем запуске/переключении.
- Чистое переключение сессии без какого-либо действия (просто «посмотрели» другую
  сессию) сервер может не сигнализировать — в этом случае сохранится активная
  сессия при первом последующем действии или выходе.

## Проверка корректности

Тесты — юнит (чистые функции, in-memory fs) и интеграционные (фейковый `client`,
временные каталоги, инъекция часов/homedir; полные сценарии
`session.created` → `message.updated` → `session.deleted` → `dispose()`).
Запущенный opencode не нужен:

```sh
node --test session-saver.test.ts
```

Нужен Node ≥ 23.6 (нативный type-stripping для `.ts`; подойдёт обычный node 24).
Тесты запускаются напрямую — без package.json и бандлера. Шов для тестов —
`createSessionSaver({ now, fs, homedir })`; дефолтный экспорт —
`createSessionSaver()` с реальными зависимостями (его и грузит opencode).

Проверка типов против SDK (`@opencode-ai/plugin`, строгий `tsc`). В репо
намеренно нет `node_modules`, поэтому tsc запускается из временного каталога:

```sh
mkdir -p /tmp/ss-tsc && cd /tmp/ss-tsc
npm init -y >/dev/null && npm i -D typescript @types/node @opencode-ai/plugin
cp "$OLDPWD"/session-saver.ts "$OLDPWD"/session-saver.test.ts .
npx tsc --noEmit --strict --types node --allowImportingTsExtensions \
  --module esnext --moduleResolution bundler --target esnext \
  session-saver.ts session-saver.test.ts
```
